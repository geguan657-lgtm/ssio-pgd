# 评测口径（读这一页再报数字）

一个「ATE = 0.34 m」在不知道**怎么对齐、比较的是哪两个坐标系**时是没有意义的。
这个包把每一处口径都做成显式参数，就是为了让你在 W2 复现不出论文数字时，能逐项排查。

---

## 1. 三个指标

### ATE — Absolute Trajectory Error（单位 m）

1. 把 est 和 gt 裁到时间重叠区间，并把 est 重采样到 gt 的时间戳；
2. 估计一个刚体/相似变换 `T`，把 est 的**位置**贴到 gt 上；
3. `e_i = || T(p_est_i) - p_gt_i ||`；
4. 报 `RMSE`、`mean`、`median`、`p95`、`max`，以及 `RMSE / GT 轨迹长度`（百分比）。

ATE 惩罚的是**全局漂移**。

### AVE — Average Velocity Error（单位 m/s，论文的主指标）

`AVE = mean_i || v_est_i - v_gt_i ||`

难点全在「哪个坐标系下的速度」：

| `--ave-frame` | 做法 | 特点 |
|---|---|---|
| `body`（推荐） | 用 **GT 姿态**把两边速度都转到 GT 体坐标系 | 完全不受航向对齐影响，**没有可调参数，无法被“调好看”** |
| `world` | 先对齐，再比世界系速度 | 与论文表格口径可能一致，但对齐方式会污染结果 |

**速度来源**（按优先级）：
1. 文件里有 `v_*` 列 → 直接用；
2. 没有 → 对位置做中心差分。

> 差分出来的速度对噪声极度敏感。200 Hz 下 1 cm 的白噪声会产生约 2 m/s 的假速度——
> 这是复现时最常见的“我的 AVE 高得离谱”的原因。

### RPE — Relative Pose Error（单位 m，按 1 m 或 1 s 分段）

段内相对位姿误差，**天然不需要对齐**，适合看局部一致性和漂移率。
本实现比较的是「各自起点体坐标系下的相对位移」，即 `|| R_i^T(p_j - p_i) - R_gi^T(p_gj - p_gi) ||`。

## 2. 对齐方式

| `--align` | 自由度 | 什么时候用 |
|---|---|---|
| `none` | 0 | 轨迹本来就在同一坐标系；或只关心相对量（RPE、body-AVE） |
| `yaw` | 1（航向）+ 平移 | 里程计已知重力方向，roll/pitch 可信，只有航向未知（**TLIO 类评测常用**） |
| `se3` | 3 + 平移 | 完全不知道初始位姿 |
| `--scale` + `se3` | 再加 1 | 单目/SfM 类带尺度不确定的结果 |

`yaw` 用 2D Procrustes（只在 xy 平面上求一个转角），比 `se3` 更不容易“吃掉”误差。

## 3. 我们踩到的第一手经验

用 `synth` 生成的已知答案做过一次对照（注入常值速度偏差 0.0539 m/s，位置噪声 1 cm）：

| 口径 | AVE |
|---|---|
| `--ave-frame body` | **0.0539**（与注入值完全一致） |
| `--ave-frame world --ave-align yaw` | 0.0557（高 3%） |

差的那 3% 不是 bug：**yaw 是从一个带线性漂移的轨迹上估出来的**，漂移让 Procrustes 估出的转角差了约 0.03 rad，3 m/s 的速度被这个转角放大成了 0.05 m/s 的假误差。

> 结论：**报 AVE 优先用 body 帧**。如果论文用世界系，你必须知道它用的对齐方式，否则数字不可比。

**第二个对照（只给位姿、没有速度列时）**：同样的数据，剥掉 `v_*` 列让评测器自己差分——

| 输入 | AVE |
|---|---|
| 带速度列 | 0.0539 |
| 只有位置（差分求速度） | **0.0917**（+70%） |

这 1 cm 的**平滑**位置噪声，光靠差分就凭空造出 0.07 m/s 的误差。
所以：**SSIO 的网络直接输出速度，而你的模型如果只输出位姿，两者的 AVE 不能直接比。**
要么让模型输出速度，要么在论文里说清楚「速度由位置差分得到」。

## 4. 六个会让数字悄悄错掉的地方

1. **时间单位**。EuRoC 是纳秒，转换错了会得到「时长 1.4e9 秒」。`verify_data.py` 会直接报出来。
2. **四元数顺序**。EuRoC 是 `w,x,y,z`；有些库是 `x,y,z,w`。顺序反了轨迹会乱跳，但 ATE 可能只是“看起来差一点”。用 `--quat-order xyzw` 显式指定。
3. **坐标系**。`p_RS_R` 是机体→世界，不是世界→机体。弄反了在长轨迹上依然能出“还行”的数字，这是最阴的一种。
4. **对齐**。见上面第 3 条：对齐方式能让 AVE 差 3%–10%。
5. **插值**。把 est 重采样到 gt 的时间戳时，线性插值会平滑掉高频误差；点太稀时误差被低估。
6. **评测范围**。只评前 30 秒 vs 全程，数字能差一倍。**必须在报告里写清楚窗口。**

## 5. 复现论文数字时的核对清单

按顺序排查，不要跳步：

- [ ] 数据集序列**完全一致**（EuRoC 用的是 MH_02 / MH_04 / V1_01 / V1_03 / V2_02 这五个）
- [ ] 评测窗口一致（是否包含开头静止段？是否截掉结尾？）
- [ ] 速度是「预测的」还是「由预测位置差分出来的」——这两者不是一回事
- [ ] AVE 是 body 还是 world；若是 world，对齐方式是什么
- [ ] 是否对每个序列单独算再取平均，还是把所有序列拼起来算
- [ ] 单位（m/s vs km/h）、是否取绝对值、是否加权

## 6. 报告模板

论文表格里每个数字都应该能追溯到一行 CSV：

```
dataset,seq,ate_rmse,ate_pct_path,ave_mean,ave_p95,align,ave_frame,n,duration_s
euroc,MH_02_easy,0.41,0.8,0.34,0.62,se3,body,21000,180.0
```

`batch` 命令生成的就是这个格式。**图里的每个点都必须能在表里找到对应行**，这是 W12 自检清单的第一条。
